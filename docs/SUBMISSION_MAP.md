## Evidence boundaries

The public transaction inventory contains 12 successful receipts and 10 distinct method types including ERC20 approve (9 core methods). Local evidence contains 13 types (12 core). Repeated calls, pause/resume variants and failed estimates do not inflate those counts. If a separate course rule excludes token approval, demonstrate an additional public core method before claiming ten core methods.

Explorer source verification remains separate from verified deployment receipts, bytecode presence and contract wiring. The supplied requirement asks for deployment details; no explorer source verification is claimed. The strategy experiment uses deterministic synthetic inputs, with negative returns retained. It is not evidence of market profitability or field adoption.

## Access and operation

Provide the assessor access to the private repository and the source archive according to the submission portal rules. Keep the public application available during marking. Before a live transaction demonstration, refresh both mock price reports from the authorized risk account. The latest public acceptance check did not restart the service; earlier non-chain jobs sentinel evidence demonstrates the observed restart persistence.

The archive is generated by scripts/package.py and excludes credentials, .git, runtime data and node_modules. GitHub retains the actual commit history; the contribution report identifies meaningful checkpoints. Artifact checksums and validation metadata are in evidence/submission-artifacts.json.
